# แผนงาน: ปรับแต่งสไลด์และอินโฟกราฟิกพร้อมระบบตรวจจับความสว่าง

## ภาพรวม (Overview)
แผนงานนี้ระบุขั้นตอนการทำงานในการติดตั้งระบบเลือกสไตล์ภาพ (Clean, Minimal, Professional) และตัวเลือกการกำหนดสีอย่างอิสระสำหรับทั้ง **สไลด์นำเสนอ (Presentation Slides)** และ **อินโฟกราฟิก (Infographics)** ใน RAG-LLM Studio โดยแผนงานนี้ประกอบไปด้วยระบบตรวจจับความสว่างของสีแบบไดนามิก (เพื่อให้สไลด์อ่านง่าย) และจานสีพรีเมียมสำเร็จรูป

---

## ประเภทโครงการ (Project Type)
- **WEB / BACKEND (Full-Stack)**
  - Backend: Python (FastAPI, Jinja2, Playwright rendering)
  - Frontend: React (Zustand state management, Tailwind CSS, Lucide icons)

---

## เกณฑ์ความสำเร็จ (Success Criteria)
1. **การรวม Schema เข้ากับระบบ**: Backend `ActionGenerateRequest` รองรับพารามิเตอร์ `style`, `primary_color`, `secondary_color`, และ `background_color`
2. **ความปลอดภัยด้าน Contrast และความง่ายในการอ่าน**: ติดตั้งฟังก์ชันตรวจหาค่าความสว่างของสี (Color Brightness Checker) โดยใช้หลักคณิตศาสตร์ HSP/Relative Luminance เพื่อสลับสีตัวอักษรระหว่างสีสว่าง/เข้มโดยอัตโนมัติตามพื้นหลัง
3. **การเรนเดอร์ Template แบบไดนามิก**: นำสไตล์และคู่สีที่กำหนดเองไปประยุกต์ใช้กับ Jinja2 HTML Templates ของทั้งสไลด์และอินโฟกราฟิกแบบไดนามิก
4. **ส่วนควบคุมพรีเมียมบน Frontend**: เพิ่มการ์ดเลือกเลย์เอาต์สไตล์, ปุ่มจานสีพรีเมียมสำเร็จรูป, และกล่องเลือกสีอิสระ (Color Pickers) เข้าไปในหน้าต่างตั้งค่าการสร้างเอกสาร (Settings Modal)
5. **ระบบบันทึกสถานะเดิม (Persistence)**: มั่นใจว่าการปรับแต่งค่าสไตล์และสีจะสามารถบันทึกและดึงกลับมาใช้ใหม่ได้อย่างถูกต้องเมื่อโหลดหน้าเว็บใหม่ (Session Recovery)

---

## โครงสร้างไฟล์ (File Structure)
- `backend/app/schemas/models.py` (เพิ่มโครงสร้างฟิลด์สไตล์และสีใน Pydantic Schema)
- `backend/app/api/routes/actions.py` (ส่งค่าพารามิเตอร์จัดแต่งสไตล์จาก API Route ไปยัง Renderer)
- `backend/app/services/renderer.py` (เขียนโค้ดฟังก์ชันคำนวณความสว่างสี, การแมปสีเริ่มต้น, และเขียน Jinja templates แบบไดนามิก)
- `frontend/src/services/api.js` (อัปเดตฟังก์ชันฝั่ง Frontend ให้ส่ง payload ไปยัง backend)
- `frontend/src/components/knowledge/KnowledgeTabs.jsx` (สร้างหน้า UI เลือกสไตล์และจานสีสวยงามในกล่องการตั้งค่า)

## ลำดับขั้นตอนการทำงาน (Task Breakdown)

### เฟส 1: โครงสร้างพื้นฐานทาง Backend (P0 & P1)

#### งานที่ 1: อัปเดต Schema ใน Pydantic
- **การดำเนินการ**: เพิ่มฟิลด์ `style`, `primary_color`, `secondary_color`, และ `background_color` เข้าไปในโมเดล `ActionGenerateRequest` ในไฟล์ `backend/app/schemas/models.py`
- **การตรวจสอบ**: ตรวจดูไฟล์ `models.py` เพื่อให้แน่ใจว่าตัวประมวลผล Pydantic ทำงานได้ถูกต้อง

#### งานที่ 2: ติดตั้งฟังก์ชันตรวจหาความสว่างสีและตั้งค่าสีเริ่มต้นใน Renderer
- **การดำเนินการ**: ในไฟล์ `backend/app/services/renderer.py` ให้พัฒนาฟังก์ชัน `is_color_light(hex_color)` โดยใช้สูตรโมเดลสี HSP และกำหนดสีเริ่มต้น (Default Colors) สำหรับสไตล์ Clean, Minimal, และ Professional
- **การตรวจสอบ**: เขียนโค้ดสคริปต์สั้นๆ ในโฟลเดอร์รันงานเพื่อตรวจสอบว่าสีขาว `#ffffff` คืนค่าเป็น `True` (สีสว่าง) และสีน้ำเงินเข้ม `#0f172a` คืนค่าเป็น `False` (สีมืด)

#### งานที่ 3: การส่งต่อพารามิเตอร์ผ่าน API Route
- **การดำเนินการ**: ในไฟล์ `backend/app/api/routes/actions.py` ให้ทำการดึงตัวแปรจัดแต่งสไตล์ออกจาก `ActionGenerateRequest` แล้วส่งต่อข้อมูลเข้าไปในการเรียกใช้ฟังก์ชัน `render_action_to_image`
- **การตรวจสอบ**: ตรวจสอบว่าพารามิเตอร์สีและเลย์เอาต์ถูกส่งไปยังส่วนเรนเดอร์ภาพอย่างถูกต้องและไม่มีข้อผิดพลาด

#### งานที่ 4: พัฒนา Slide Template แบบไดนามิก
- **การดำเนินการ**: ปรับปรุง `SINGLE_SLIDE_HTML_TEMPLATE` ใน `backend/app/services/renderer.py` ให้ใช้ตัวแปรทับค่าสี Tailwind CSS และเขียนเงื่อนไข HTML/Tailwind สำหรับรูปแบบเลย์เอาต์ที่เลือกตามสไตล์ โดยนำฟังก์ชัน `is_color_light` มาตรวจสอบสีพื้นหลังเพื่อสลับฟอนต์ระหว่างสีมืด/สว่าง (`text-slate-100` / `text-slate-900`) และปรับสีกรอบการ์ดและไอคอนให้เหมาะสม
- **การตรวจสอบ**: Backend สามารถประมวลผลสไลด์และส่งคืนภาพ Base64 ที่เรนเดอร์อย่างถูกต้องสวยงาม

#### งานที่ 5: พัฒนา Infographic Template แบบไดนามิก
- **การดำเนินการ**: ปรับปรุง `INFOGRAPHIC_HTML_TEMPLATE` ให้ใช้รหัสสีหลัก สีรอง และสีพื้นหลังที่ผู้ใช้ส่งมา พร้อมระบบคำนวณความสว่างสีเพื่อรักษาความเปรียบต่างให้อ่านง่าย
- **การตรวจสอบ**: ทดลองส่งชุดคู่สีจัดอินโฟกราฟิกและตรวจสอบภาพ Base64 ผลลัพธ์ว่าใช้สีที่ถูกต้อง

---

### เฟส 2: การพัฒนาฝั่ง Frontend (P2)

#### งานที่ 6: เชื่อมต่อ API Payload
- **การดำเนินการ**: ในไฟล์ `frontend/src/services/api.js` ปรับปรุงฟังก์ชัน `generateKnowledgeAction` ให้รับตัวเลือก `style`, `primaryColor`, `secondaryColor`, และ `backgroundColor` เพิ่มเติมและแมปเข้าไปยัง Payload คำขอ HTTP
- **การตรวจสอบ**: ตรวจสอบค่า Payload ของคำขอที่ส่งออกทาง Network ในเบราว์เซอร์ว่ามีตัวแปรถูกส่งออกไปจริง

#### งานที่ 7: พัฒนา UI เลือกสไตล์และจัดสีสันสไลด์
- **การดำเนินการ**: ปรับปรุง UI ของ Modal หน้าเลือกตั้งค่าก่อนสร้างเอกสารใน `frontend/src/components/knowledge/KnowledgeTabs.jsx`:
  1. **สไตล์เลย์เอาต์การ์ด** (Clean, Minimal, Professional) พร้อมตัวอย่างข้อความอธิบายความแตกต่าง
  2. **ตัวเลือกเปิด/ปิดโหมดแต่งสีอิสระ** (สีเริ่มต้นอัตโนมัติ vs กำหนดสีเอง)
  3. **แถบจานสีพรีเมียมสำเร็จรูป** (เช่น Ocean Blue, Cyberpunk, Forest Green, Earthy Beige, Charcoal Gold) ที่คลิกปุ่มเดียวสามารถแต่งสี Primary/Secondary/Background ทั้งชุดได้ทันที
  4. **ช่องเลือกสี Color Picker** โดยใช้แท็ก `<input type="color">` ในกรณีที่อยากแต่งสีเฉพาะส่วนเองอย่างอิสระ
- **การตรวจสอบ**: เปิดหน้าเว็บ, กดเลือก Slides/Infographics, เลือกปรับแต่งค่าสไตล์และจานสี ตรวจสอบว่า state ฝั่ง React อัปเดตและสามารถเชื่อมโยงค่าสีที่เลือกส่งผ่าน API ได้ถูกต้อง

### 2. รันแอปพลิเคชันเพื่อทดสอบจริง (Live Check)
- สตาร์ท Backend ด้วย uvicorn และสตาร์ท Frontend ด้วย npm run dev
- เข้าสู่ระบบ RAG อัปโหลดเอกสารต้นฉบับ จากนั้นคลิก **สร้างสไลด์นำเสนอ (Slides)** เพื่อเปิดกล่องตัวเลือก

- ตรวจสอบว่าภาพผลลัพธ์ที่ได้ใช้สีแนว Cyberpunk และตัวหนังสือสามารถอ่านได้ชัดเจน
- ลองทดสอบใหม่อีกครั้งโดยเปลี่ยนสีพื้นหลังเป็นสีสว่างมาก (เช่น ขาว `#ffffff`) เพื่อตรวจสอบว่าระบบ **Color Brightness Checker** สลับตัวอักษรและไอคอนทั้งหมดในหน้าจอเป็นสีมืด (เข้ม) โดยอัตโนมัติเพื่อให้อ่านง่ายหรือไม่
