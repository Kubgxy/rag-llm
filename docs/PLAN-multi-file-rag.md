# PLAN: เพิ่มการรองรับไฟล์หลายประเภทสำหรับระบบ RAG (Ingestion & Querying)

แผนงานนี้จัดทำขึ้นสำหรับการเพิ่มความสามารถในการอัปโหลดและสืบค้นเอกสารอีก 5 ชนิด เข้าสู่ระบบ RAG (จากเดิมที่จำกัดเฉพาะ PDF):
- **กลุ่มข้อความ (Text-based)**: `.txt`, `.md`, `.docx`, `.pptx`
- **กลุ่มตาราง (Tabular)**: `.csv`, `.xlsx`

---

## 📋 ภาพรวม (Overview)
ปัจจุบันระบบสามารถอัปโหลดและตั้งคำถามได้เฉพาะไฟล์ PDF เท่านั้น แผนการพัฒนานี้จะขยายความสามารถทั้งฝั่ง Frontend และ Backend ให้รองรับไฟล์ `.txt`, `.md`, `.docx`, `.pptx`, `.csv`, และ `.xlsx`

สำหรับกลุ่มข้อความ (Text-based) จะใช้ไลบรารีสกัดคำเพื่อแปลงข้อมูลแยกเป็นส่วนย่อยตามหน้าจำลอง (Pseudo-pages) เพื่อให้สอดรับกับสถาปัตยกรรมแสดงแหล่งอ้างอิงหน้าเอกสาร (Citation Pages) บนหน้าต่างสนทนา ส่วนกลุ่มตาราง (Tabular) จะใช้วิธีเทข้อมูลลงฐานข้อมูล SQLite และส่งต่อคำสั่งให้ AI Agent (`qwen2.5-coder:7b`) เขียนโค้ด Python/SQL เพื่อดึงข้อมูลมาตอบ แทนการส่งเนื้อหาดิบของตารางเข้า Prompt โดยตรง เพื่อรักษาขอบเขต Context และตอบคำถามคำนวณหรือสถิติได้อย่างแม่นยำ

## 🎯 เกณฑ์ความสำเร็จ (Success Criteria)
1. ผู้ใช้งานสามารถอัปโหลดไฟล์ `.pdf`, `.txt`, `.md`, `.docx`, `.pptx`, `.csv`, และ `.xlsx` ขนาดสูงสุด 30 MB ได้อย่างถูกต้อง
2. ระบบสามารถประมวลผลไฟล์กลุ่มข้อความ (`.txt`, `.md`, `.docx`, `.pptx`) เข้าสู่ pgvector โดยสร้างเลขอ้างอิงหน้า (Citation Pages) ที่เหมาะสม
3. ระบบสามารถบันทึกข้อมูลตารางจากไฟล์ `.csv` และ `.xlsx` เข้าสู่ฐานข้อมูล SQLite (`data/tabular.db`) อัตโนมัติหลังอัปโหลด
4. การถามตอบเกี่ยวกับข้อมูลตารางจะส่งไปที่โมเดล `qwen2.5-coder:7b` เพื่อให้เขียนโค้ดวิเคราะห์ข้อมูล รันผลลัพธ์ผ่าน Sandbox และนำผลสรุปมาตอบผู้ใช้
5. ผ่านการตรวจสอบด้วยสคริปต์สแกนโค้ดและความปลอดภัยทั้งหมดโดยไม่มีบล็อกเกอร์

## 📝 รายละเอียดขั้นตอนการดำเนินงาน (Task Breakdown)

### Phase 1: การติดตั้งไลบรารีและสร้างฟังก์ชันสกัดเนื้อหา (P0)
เตรียมสภาพแวดล้อมและพัฒนาส่วนควบคุมสำหรับการดึงข้อความแต่ละฟอร์แมต

#### Task 1: ติดตั้งแพ็กเกจการจัดการไฟล์แบบใหม่
- **ผู้รับผิดชอบ**: `backend-specialist`
- **ทักษะที่เกี่ยวข้อง**: `python-patterns`
- **ระดับความสำคัญ**: P0
- **การพึ่งพา**: ไม่มี
- **INPUT**: แก้ไขไฟล์ requirements.txt
- **OUTPUT**: เพิ่มรายการ dependencies: `python-docx`, `python-pptx`, `pandas`, `openpyxl`
- **VERIFY**: รันคำสั่ง `pip install -r backend/requirements.txt` และตรวจสอบว่าติดตั้งผ่านสมบูรณ์

#### Task 2: เขียนฟังก์ชันตัวสกัดข้อความ (File Parsers)
- **ผู้รับผิดชอบ**: `backend-specialist`
- **ทักษะที่เกี่ยวข้อง**: `python-patterns`
- **ระดับความสำคัญ**: P0
- **การพึ่งพา**: Task 1
- **INPUT**: สร้างไฟล์ parsers.py
- **OUTPUT**: โค้ดประมวลผลไฟล์แต่ละนามสกุล:
  - `extract_text_from_docx(file_path)`: แบ่งกลุ่มย่อหน้าทุก 1,000–1,500 ตัวอักษร คืนค่าเป็น `Dict[int, str]` (หน้าจำลอง)
  - `extract_text_from_pptx(file_path)`: สกัดทีละสไลด์ คืนค่าเป็น `Dict[int, str]` (1 สไลด์ = 1 หน้าจำลอง)
  - `extract_text_from_txt_md(file_path)`: อ่านข้อมูลดิบและจัด Chunk ย่อหน้าทุกๆ 1,000–1,500 ตัวอักษร คืนค่าเป็น `Dict[int, str]`
  - `ingest_tabular_file(file_path, filename, session_id)`: ใช้ pandas โหลดข้อมูลตารางและส่งเข้าไปเซฟใน `data/tabular.db` ภายใต้ชื่อตารางเฉพาะ `table_<session_id>_<safe_filename>`
- **VERIFY**: สร้างการทดสอบสั้นๆ สำหรับแกะไฟล์จำลองชนิดต่างๆ ว่าให้โครงสร้างหน้าและสามารถบันทึกลง SQLite ได้อย่างถูกต้อง

  - ตรวจจับสกุลไฟล์เพื่อกำหนด `mime_type` และ `source_type` ที่เหมาะสมในตาราง `documents`

#### Task 4: ปรับปรุงส่วน Ingestion Pipeline
- **ผู้รับผิดชอบ**: `backend-specialist`
- **ทักษะที่เกี่ยวข้อง**: `python-patterns`
- **ระดับความสำคัญ**: P1

    - DOCX/PPTX/TXT/MD → ดึงข้อมูลแยกหน้าและสร้าง Vector Store
    - CSV/XLSX → เรียกใช้ `ingest_tabular_file` เพื่อจัดเก็บข้อมูลลง SQLite และข้ามการประมวลผล Vector ชั่วคราว (หรือสร้าง Vector สรุปเบื้องต้นเพื่อใช้เป็นหัวข้อสืบค้น)
- **VERIFY**: ทดสอบการอัปโหลดไฟล์ประเภทต่างๆ และตรวจสอบว่าสถานะใน PostgreSQL ถูกเปลี่ยนเป็น `completed` ทั้งหมด

### Phase 3: การเชื่อมโยงคำถามสำหรับไฟล์ตารางโดยใช้ Code-Gen Agent (P1)
จัดทำระบบวิเคราะห์สืบค้นตารางโดยการรันโค้ดวิเคราะห์ข้อมูลอย่างชาญฉลาด

#### Task 5: ระบบดักจับคำถามและรันโค้ด Python
- **ผู้รับผิดชอบ**: `backend-specialist`
- **ทักษะที่เกี่ยวข้อง**: `python-patterns`
- **ระดับความสำคัญ**: P1
- **การพึ่งพา**: Task 4
- **INPUT**: แก้ไขไฟล์ llm_service.py
- **OUTPUT**:

  - ถ้ามีคำสั่งและเกี่ยวข้องกับข้อมูลตาราง:
    1. ทำการอ่านโครงสร้างคอลัมน์ (Schema) ของตารางนั้นๆ ใน SQLite

- **VERIFY**: เมื่อถามข้อมูลในตาราง เช่น "ยอดขายเฉลี่ยในเดือนมกราคมคือเท่าไหร่" ระบบจะพิมพ์แสดงผลสรุปตัวเลขสถิติจากการรันโค้ดหลังบ้านได้

### การทดสอบด้วยระบบผู้ใช้งาน (Manual Verification)
1. **ไฟล์กลุ่มข้อความ (TXT / MD)**: อัปโหลดเอกสาร `.txt`/`.md` ทดสอบแชท และตรวจสอบว่า Citation ชี้จุดเลขหน้าจำลองได้ถูกต้อง
2. **ไฟล์สไลด์และเอกสาร (DOCX / PPTX)**: อัปโหลดสไลด์ ตรวจสอบว่าแชทแยกหน้าสไลด์ตรงกันอย่างแม่นยำ (หน้าสไลด์ 1 = หน้าอ้างอิง 1)
3. **ไฟล์ตารางสถิติ (CSV / Excel)**: อัปโหลดไฟล์ประวัติคำนวณยอดขาย ทดสอบพิมพ์ถาม "ยอดขายรวมของพนักงานชื่อ A คือเท่าไหร่" ตรวจสอบดู Console ของ Backend ว่าตัว Agent `qwen2.5-coder:7b` ทำงานจริง และตอบกลับมาถูกต้องตามเลขในตาราง
4. **ความปลอดภัยและการดักจับความผิดพลาด**: อัปโหลดสกุลไฟล์ต้องห้ามอื่นๆ เช่น `.png` หรือ `.zip` แล้วตรวจสอบความเรียบร้อยว่าแสดง Toast สีแดงเตือนระบบไม่รองรับอย่างชัดเจน
